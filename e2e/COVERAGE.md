# E2E coverage

Playwright journeys in `e2e/journeys/`, signed in once through the real Auth
SPA by `e2e/auth.setup.ts`. `e2e/coverage.json` is the checkpoint list; keep
it in sync when user-facing behavior changes.

| Journey | Checkpoints                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| auth    | A1 lands on `/platform/<org>` · A2 tokens + tenants stored · A3 URL org = session org · A4 the checkout's return moves to the own org                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| shell   | S1 sidebar navigation · S2 ⌘K palette · S3 OS footer cluster · S4 admin gate                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| recruit | C1 prospect · C2 school · C3 application → board → enrolled · C4 activity · C5 tag · L1 public page 404 · L2 landing-page draft                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| sample  | D1 notice + applications on `main` · D2 prospects → a prospect · D3 schools, applications, activities, tags · D4 a write upgrades · D5 Upgrade for free → the $0 checkout (skips until web-containers carries `checkoutUrl`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| house   | H1 a main-only user lands in the shell, admin cluster shown · H2 a trial-gated click upgrades · H3 a visitor is previewed and can join · H4 Create Your Own Platform → the $0 sign-up · H5 an admin's setup flow skips the known name → home · H6 a finished admin stays home · H7 a member's form → home · H8 nothing configured → home · H9 Back to My Platform · H10 Management › Onboarding link on `/platform/<org>/onboarding/` · H11 a set sector leaves only the team step · H12 the sample with its admin rows · H13 a write upgrades · H14 Upgrade for free → the $0 checkout · H15 the checkout's return moves to the own org · H16 Upgrade Plan returns through the sign-in app (H1–H4, H7–H9, H12–H14 skip without the member pair) |

Run: `pnpm test:e2e` (all browsers), `pnpm test:e2e:ui`, `pnpm test:e2e:headed`.
Credentials go in `e2e/.env.development`: `pnpm e2e:accounts` creates an admin and a member in the
throwaway organization `iblai.env` names and writes them there.
