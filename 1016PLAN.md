# Persist the User / Admin mode (e2e S4)

## Context

Journey S4 ("a member, or an admin in User mode, never sees Settings") fails. An admin switches to User mode, then a full page load of `/platform/<org>/settings` starts in Admin mode again, so Settings renders instead of sending them home.

The mode is plain React state: `components/crm/admin-mode.tsx`, `const [mode, setMode] = useState(true)`.

rei decided on 2026-10-16: persist the mode.

**This differs from the OS on purpose.** The OS keeps its switch in the Redux `isInstructorMode` (`features/users/slice.ts`, `initialState: true`), and its store isn't persisted. iblai/crm and the SIS have the same in-memory `useState(true)`. Those three are not part of this change.

## Change: `components/crm/admin-mode.tsx`, one file plus one prop

- **Storage.** User mode is kept in `localStorage` under `recruit:user-mode:<tenantKey>`, with the value `"1"`. Switching back to Admin removes the key; no key means Admin, as today.
  - `AdminModeProvider` reads the key in its `useState` initializer and writes or removes it in its setter.
  - The setter is the only writer. `AdminModeSwitch` and the `AdminGate` redirect stay as they are.
- **The prop.** `AdminModeProvider` takes `tenantKey`. `app/(app)/platform/[tenantKey]/layout.tsx` already has it from `useSession()` and passes it.
- **Per organization**, because two organizations can be open in two tabs at once.
- **Why `localStorage`:**
  - it survives a reload and new tabs;
  - the SDK clears it on sign-out, on the redirect to sign in (an expired session, a 401) and on an organization switch: `localStorage.clear()` in web-utils 2.9.0's `handleLogout`, `redirectToAuthSpa` and `handleTenantSwitch`. So a normal sign-in starts in Admin. `SsoLogin` itself clears nothing (web-containers 1.43.0 `initializeLocalStorageWithObject`), so a session handed straight to `/sso-login-complete` with no sign-out here keeps the mode;
  - sessionStorage would lose the mode in a new tab, and a cookie would outlive the sign-in.
- **No server guard is needed.** `IblaiProviders` (`app/(app)/layout.tsx`) renders only the loading screen until the client mounts (`providers/iblai-providers.tsx`), so the initializer only runs in the browser.
- **What follows the persisted mode:**
  - the sidebar (`isLiveAdmin`, the admin-only rows);
  - the Settings and Users gate;
  - the chat's `userIsStudent`.

  Members are unaffected: `adminMode` stays `isAdmin && mode`.

- **The doc comment** gets one line: "Kept per organization in localStorage; signing out or switching clears it."

Nothing else changes. There's no cross-tab live sync: an already-open tab picks the mode up on its next load. Add sync if someone asks for it.
